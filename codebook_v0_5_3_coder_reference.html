How to work

Three passes over the document, not one. Doing extraction, routing, and filling together for each sentence means reloading every rule fifty times over. Split them and each rule gets loaded once.

Pass 1 — extraction only

Spreadsheet closed. Read the document end to end, then go back and highlight. Three questions per passage, in this order:

What is this passage about?Name the family. Or: framework-wide infrastructure. Or: a non-CBRN hazard only. If infrastructure — does the document say it switches on at a stated line, or is it always on? Always-on is out.
Is there something here that either happened or didn't?Not "is it true" and not "is it arguable" — is there a fact of the matter. "We take safety seriously" has nothing to check. "We evaluate for biological uplift before release" either happens or it doesn't.
Have I already highlighted this same assertion?Core gates restate three to five times. Mark it as a locator on the first one.
Is the only content a read-off document property?A named multilateral commitment, a version property, an evaluator access term. Mark it for the Document facts sheet. Publication commitments are claims — they stay in the claim list.

Output: highlighted passages with a family written in the margin. Nothing typed into the sheet yet.

watchCompare extraction lists with your co-coder now, before Pass 2. Filling fields for records that shouldn't exist is the most expensive mistake available.

Pass 2 — routing

For each highlighted passage, one question: which group does this fill? Usually one, sometimes two. If two, ask whether the fields diverge — different claim type, hazard, decision point, or backing means it is a split, so two records.

Output: a numbered list of record id, locator, and group name. Still almost no typing.

Pass 3 — filling, column-wise

Set the 18 document-level fields once and paste them down every row. Fill the 5 always-coded fields. Then work one group at a time across all claims — every hazard claim together holding Rule 1 in mind, then every threshold claim together holding Rules 3 and 3a, and so on.

This is where the time goes if you do it row by row. Column-wise, you hold one rule and apply it eight times instead of holding ten rules and applying each once.

Then the Document facts row for this framework: the 4 access-term fields, plus evidenced_by, evidence_locator and evidence_verbatim from whatever you marked in Pass 1.

Last: Rule 6 over every remaining blank.

The rules are not a sequence

Ten rules, but no claim meets more than four or five. Rule 0 is a gate applied to every passage. Three rules apply to every record. The rest hang off a single group and fire only if a claim routes into it.

Rule 0Every passage. Scope, then falsifiable, then does a field fit.
Rules 5, 6, 7Every record. Claim type if signatory; absence; dual frameworks.
Rule 1Only if you routed to the hazard group.
Rules 3, 3aOnly if you routed to the threshold group.
Rule 8Only if you routed to external input or third party.
Rule 4Not part of coding a claim at all — the Tier A checklist, filled from finished records.

watchRule 3 is a filling instruction for the threshold group, not part of the claim test. A claim that routes to decision point never meets it. Decision point, accountability, override route, and evaluation have no extra rule at all.

00

Before you start a document

Eighteen fields describe the document, not any claim in it. Set them once, paste them down every row, and never think about them again.

Document-level fields — set once

company · source.framework_role · source.framework_name · source.instruments_named · source.commitments_named · source.companion_document · source_url · source_version · source_publication_date · access_date · all five version.* fields · all three applicability.* fields

watchThe version.* fields record whether the document has a changelog, version number, date, and rationale. A claim promising future updates does not populate them — that claim codes decision_point = framework_revision.

alsoFour further fields are document properties and live only on the Document facts sheet, never on a claim row: the Measure 3.5 access terms (qualification_criteria_published, non_retaliation_commitment, disclosure_delay_cap, fewest_mitigations_version_access). No claim in any coded framework asserts them, which is why recording them per framework is what makes their absence a supported finding. Cite evidencing record ids in evidenced_by or state that none exist, with the passage in evidence_locator and evidence_verbatim.

Then read the whole document once, before extracting

Most of what you read will not become a record. Front matter typically yields nothing. Several pages without an extraction is normal, not under-coding.

01 · Rule 0, step 1

Is this passage in scope

Scope is decided by commitment family, not by topic relevance. Ask what the passage is about before asking whether it is a claim.

In scope — these nine families, and where each one codes

Families are the vocabulary of the scope test: what a passage is about. Conditional groups are the vocabulary of field routing: what you fill in. Eight families map straight onto a group. One does not — see the last row.

Hazard definitions and coveragehazard.*
Capability thresholds and triggered responsesthreshold.*
Development and deployment decision pointsdecision_point
Governance backing for risk decisionsbacking_mechanism.* · separation_of_duties
Third-party evaluation accessthird_party.*
Evaluation reportingevaluation.*
External input into risk decisionsexternal_basis
Override and waiver routesoverride_waiver_route
Framework versioning and revisiondecision_point = framework_revision
No group of its own. The five version.* fields are document-level and are never populated from a claim.

watchA claim promising future updates is in scope and is a claim. It codes decision_point = framework_revision — looking for a version.* field to fill is the wrong turn.

Out of scope — framework-wide infrastructure

Security posture, incident response operations, legal and compliance machinery. Out even where they apply to CBRN risks: a measure that applies identically to every hazard carries no signal about whether biological risk is treated differently, which is the research question.

exceptionAlways-on or switched-on? Ask what the document says, not why the measure exists. Every security control exists because risks exist — that is motivation, not a trigger. Weight encryption applies to every model all the time: always-on, out of scope. "We will require the following practices for High capability models" switches on at a stated line: in scope.

If the line is new, make a threshold record with the measures as its response. If the line is already a coded record, append the locator to that record — do not create a second one.

watchThe line does not have to name a hazard. "High capability models" is a capability level and it counts. What does not count is the ambient fact that risks exist.

Hazard universe

In scope where the claim concerns C, B, R, or N content, or applies across all tracked categories. A claim scoped only to a non-CBRN hazard — cyber-only, self-improvement-only — is out.

inA non-CBRN threshold that cites CBRN as a downstream consequence stays in. Note the indirect framing.

02 · Rule 0, step 2

Is this passage a claim

Both conditions must hold. Then every passage takes exactly one of three exits.

a

Is there something that either happened or didn't?

Not "is it true", and not "could it be argued". You are never assessing whether the company is being honest — only whether the sentence points at something determinate. It names an action, condition, threshold, actor, process, or trigger.

noMission statements, undefined commitments to abstractions, recital-style framing, definitions without an attached obligation.

watchThis test asks about the whole passage. It is not the same as asking whether a condition clause is specific enough to be a threshold — that is Rule 3, and it only comes up if you route to the threshold group. A claim can pass this test and have no threshold at all.

b

Field mapping

Can you populate at least one conditional field from it — hazard, threshold, decision point, backing mechanism, third-party access, evaluation reporting, versioning, external basis, override route?

Disposition — exactly one exit

Out of scopeSkip. Do not log.
In scope, but no field fitsLog in the field-gap log. Do not force a fit.
In scope and a field fitsMake a record.
In scope, but the only content is a read-off document propertyNot a claim record. Record it, its locator and its verbatim on the Document facts sheet. This covers named multilateral commitments, version properties, and evaluator access terms — things no claim asserts. It does not cover publication commitments.

watchNever reason about what a passage might imply in order to rescue it into a field. The scope test and the fields do the filtering — that is the safeguard against pulling text toward a preferred conclusion.

notePublication commitments are claims, not document properties. "We will publish public summaries of these assessments" is a Measure 10.2 commitment — it codes in the evaluation group with a claim type and its hedges intact (e.g. "standalone reports or system cards"). Only things no claim asserts go to Document facts.

03 · Rule 0

Where a claim begins and ends

The unit is one assertion, not one sentence.

Split when fields diverge

Different hazard, claim type, decision point, or backing mechanism in the same passage means two records. That divergence is the tell.

Merge across sentences when the assertion requires it

A threshold definition and its triggered response belong together. But never merge across sections — a section is any headed division as published; where there are no headings, treat page breaks as boundaries.

Deduplicate within a document

A later passage restating an already-coded claim, with no field value changing, is not a new record. Append its locator to the existing record and code the most complete statement as canonical. If any field value would differ, it is a new record.

watchThis is the single biggest source of inflated record counts. Core gates often restate three to five times in one framework.

Keep verbatim tight but self-contained

If a reader cannot tell what the claim is without the preceding sentence, include it. Section references live in source_locator, never inside claim_text_verbatim.

04

Which fields to fill

Fifty fields, three tiers. Only the third asks anything of you.

tier 1 · 18 fields

Document-level

Set once per document, copied to every row. No per-claim decision. A further four live only on the Document facts sheet.

tier 2 · 5 fields

Always coded

record_id, claim_text_verbatim, claim_type, source_locator, coder_notes.

tier 3 · 23 fields

Conditional

Ask one question: what is this claim about? Populate that group, and put not_applicable in every group you did not route to.

The eight conditional groups

hazardThe claim names or defines a hazard, or describes what a model could enable.
thresholdThe claim states a capability level or condition the company monitors.
decision_pointThe claim says what happens to a model — or to the framework itself. Revision commitments land here as framework_revision; there is no separate versioning group.
backing_mechanism + separation_of_dutiesThe claim names who oversees, owns, supports, or assures a risk decision.
override_waiver_routeThe claim states whether commitments can be adjusted downward.
external_basisOutside actors provide input directed at a decision object.
third_party.*The claim concerns evaluation of the model by outsiders. external_evals and named_evaluators only — the four Measure 3.5 access terms live on the Document facts sheet.
evaluation.*The claim states when a model is re-evaluated, or commits to publishing results (Measure 10.2).

Worked example

"We expect our approach will continue to evolve, and we will update this FGF as our processes and regulatory requirements change."

Document-level: already set. Always-coded: yes. What is it about? Framework revision — so decision_point = framework_revision, and nothing else in tier 3. Not versioning (those fields describe the document). Not instruments_named despite "regulatory requirements" (document-level, already recorded). One conditional field.

06 · Rule 6

Recording absence

Absence handling is where the dataset's credibility lives. Blank never means "nothing here" — blank means not yet coded.

Three kinds of absence, never collapsed

Affirmative negationThe document states the thing does not exist or is not permitted → none_stated, no_route_stated.
SilenceThe document does not address it → not_publicly_specified.
Out of scopeThe obligation does not apply → out_of_scope.

Not absence codes

not_applicable and not_hazard_specific are scope values: the claim does not route to that group. Every conditional group you did not route to takes not_applicable — blank means only one thing, not yet coded. Absence within a group you did route to still follows the three-way taxonomy above.

unclear belongs only to the applicability fields, where public information is insufficient to determine status.

unspecified appears only in version.ratchet_direction, where it follows the borrowed Safety Framework Cards vocabulary.

07

Special cases

The rules that fire less often but change the code when they do.

Substitution test — Rule 1

Swap "biological" for "chemical". If the sentence stays coherent and equally applicable, the treatment is generic. If it breaks, it is bio-specific.

yespathogen enhancement, de novo synthesis, CDC Class A agent, pandemic preparedness, nucleic acid screening

no"evaluate uplift for CBRN weapons", "harmlessness training and output monitoring", "biological or chemical threats"

Signatory asymmetry — Rule 5

The Code's glossary defines appropriate, best practice, and state of the art. For a signatory these carry defined content, so "appropriate mitigations" codes binding_internal_policy rather than a hedge. For a non-signatory the same words stay stated_aspiration.

watchOnly those three glossary terms convert. Ordinary hedging — "may", "as available", "where feasible" — stays hedged for signatories too.

Dual frameworks — Rule 7

Some companies publish two frameworks: one written against legal obligations, one voluntary. Code every claim with source.framework_role. Never average or merge across them.

Identical text in both is coded twice — the unit is claim-in-document — and linked with XDOC-DUP. Field values may legitimately differ between the twins; that divergence is a finding, not an error.

A research or methodology preprint is not a second framework.

Routing external engagement — Rule 8

external_basisInbound, and directed at a decision object: thresholds, evaluations, risk acceptance, deployment, framework revision.
third_party.*Evaluation of the model, or access for evaluation.
skipOutbound sharing, general fora membership, bug bounties, vulnerability disclosure, threat sharing — security-ecosystem engagement is infrastructure.

Thresholds — Rules 3 and 3a

A threshold is any stated capability level or condition presented as a line the company monitors. A response is not required for the record to exist — the link is coded in threshold.response_linked.

Tier tables whose responses live in another section are the paradigm response_linked = no case. Cross-reference by record id; never merge across sections.

watchRe-evaluation commitments are not thresholds. They state no monitored capability line — code them in evaluation.reevaluation_trigger_stated only.

Bio-engagement checklist — Rule 4

Tier A only, recorded in the checklist sheet, present or absent with no adequacy judgment. Each yes must cite the record id evidencing it; a yes with no citable record is not a yes.

  • Distinguishes informational uplift from end-to-end operational capability
  • Addresses tacit knowledge or protocol troubleshooting
  • References acquisition chokepoints
  • Specifies an actor model (novice vs trained)
  • Treats biological design tools separately from language models
  • Names agent or pathway classes rather than generic "bioweapons"

Notes and tokens

Three controlled tokens in coder_notes, so the notes column stays searchable.

CALIBRATIONA contestable call. Flag it, code your best judgment, and move on — these are the comparison set for the calibration meeting, not problems to resolve alone.
RULE5-ASYMSignatory status changed the code on this record.
XDOC-DUP: idThe same or near-identical text appears in the companion framework at that record.

The standing reminder

Record whether a framework addresses what a commitment asks about. Never whether the provider complies. Compliance is not determinable from public documents.
